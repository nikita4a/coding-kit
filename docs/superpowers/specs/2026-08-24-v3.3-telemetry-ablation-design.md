# Cost/Duration Telemetry + Skill Ablation — Design & Decision Record

> Status: approved design, implemented in v3.3.0. This replaces the superseded
> 795-line preliminary draft with the corrected design actually shipped.
> The checklist states reflect the current `eval/` code and `tests/` only —
> nothing here is asserted beyond what those files substantiate.

## Goal

Make model choice a measured decision, not a blind one:

- every eval result doc carries aggregate wall-clock (`duration_s_total` /
  `duration_s_mean`) and, when a user supplies `--usage-json`, user-reported
  `{tokens_total, cost_usd}`;
- a controlled inlined-prompt ablation measures each skill's inlined
  contribution to pass-rate, reported as an experimental (descriptive) metric.

## Why the original design was corrected

The 2026-08-24 draft specified several interfaces that drifted from what
shipped. Each correction is backed by the current code and its regression
test:

1. **`run_scenarios` stays a public `int`, via the internal evaluator.**
   The draft assumed a row-returning contract. The real seam is
   `_evaluate_scenarios(...) -> (exit_code, rows)`; the public
   `run_scenarios` wraps it and returns the process exit code.
   `eval/ablate.py` imports `_evaluate_scenarios` directly so it reuses the
   executor+judge loop with a `disable` set (`eval/ablate.py`,
   `eval/runner.py`).
2. **Telemetry covers all three eval runners.** `eval/telemetry.py` is
   consumed by trap (`runner.py`), tasks (`task_runner.py`), and trigger
   (`trigger_eval.py`) — not just trap/tasks as the draft's "Phase A"
   implied.
3. **`reported_usage` is live-only, never fabricated.** The `--usage-json`
   payload key lands in a result doc only on a live run; dry-run never
   parses the file. The value is reported by the user from the provider
   dashboard — the harness measures wall-clock only
   (`eval/telemetry.py`, `tests/test_telemetry.py`,
   `tests/test_json_output.py`, `tests/test_task_runner.py`,
   `tests/test_trigger_eval.py`).
4. **Ablation has an executable CLI and a `kitctl ablate` command.**
   `eval/ablate.py` is a runnable script (`--executor/--judge/--model/
   --repeat/--timeout/--scenario/--skills-dir/--json/--usage-json`), and
   `scripts/kitctl.py` dispatches `ablate` to it (`scripts/kitctl.py`,
   `tests/test_kitctl.py`, `tests/test_ablate.py`).
5. **Neutral repo `cwd`, HOME/auth retained.** Executor subprocesses run
   from a per-call temp directory (`cwd=neutral`), preventing automatic
   discovery of repo-local instruction/config files through the inherited
   `cwd`; ambient global skills and general filesystem access remain
   uncontrolled. `executor_env()` still forwards HOME/USERPROFILE/APPDATA
   (auth) while dropping secret-bearing variables (`eval/runner.py`
   `run_prompt`, `tests/test_prompt_inline.py`, `tests/test_json_output.py`,
   `tests/test_task_runner.py`).
6. **The metric is experimental inlined-prompt contribution, not
   causal/deletion evidence.** A treatment removes a skill's descriptor +
   body from that experiment's assembled prompt only; it never deletes the
   skill, and the delta is descriptive — ambient global skills already
   loaded by the host harness are NOT controlled. The result doc carries
   `experimental: true`, `ambient_skills_controlled: false`, and
   `metric: "inlined-prompt contribution"` (`eval/ablate.py`,
   `tests/test_ablate.py`).
7. **One `kind="ablate"` doc.** `run_ablation` persists exactly one result
   document (no intermediate trap docs); `results_io.VALID_KINDS` gains
   `"ablate"` (`eval/ablate.py`, `tests/test_ablate.py`,
   `tests/test_results_io.py`).
8. **Raw trend table + caveat.** `trend.py` renders the newest ablation per
   model in a separate raw table under an explicit "ambient skills
   uncontrolled / small samples non-conclusive" caveat, and excludes
   `ablate` docs from the main `(kind, model)` table (`eval/trend.py`,
   `tests/test_trend.py`).

## Delivered surface

| Component | Result |
|---|---|
| `eval/telemetry.py` | `summarize_durations(rows) -> (total_s, mean_s)` over finite non-negative attempts; `load_reported_usage(path) -> dict \| None` (validated `{tokens_total, cost_usd}` subset). |
| `eval/prompt_assembly.py` | `parse_frontmatter`, `skill_manifest`, `assemble_prompt` (manifest + one inlined active-skill body; `disable` honoured). |
| `eval/runner.py` | `--inline-skills`, `--skills-dir`, `--disable-skill`; neutral temp `cwd`; duration aggregates + live-only `reported_usage`. |
| `eval/task_runner.py` | duration aggregates + live-only `reported_usage`; six-class failure taxonomy; fresh fixture sandbox per attempt. |
| `eval/trigger_eval.py` | per-attempt timing + duration aggregates + live-only `reported_usage`. |
| `eval/ablate.py` | experimental per-skill inlined-prompt contribution; one `kind="ablate"` doc; CLI + `kitctl ablate`. |
| `eval/trend.py` | duration/cost columns in the main table; raw ablation section with caveat. |
| `eval/results_io.py` | `VALID_KINDS` + `"ablate"`. |
